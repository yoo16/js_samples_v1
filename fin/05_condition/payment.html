処理の流れ

画面は5つ用意してあり、showStep(n) で表示する画面を切り替えます。ボタンを押すと、対応する関数が呼ばれます。

画面 ボタン 呼ばれる関数 やること
1. レジ袋 利用する / しない chooseBag() 合計金額を変える
2. ポイント 読み取る / 持っていない scanPointCard() カードの有無を覚える
3. お支払い 決済方法 / 次へ selectMethod()
goToConfirm()		 表示の切り替え、入力チェック
4. 決済 決済する handlePayment()
completePayment()		 現金なら所持金を引く
5. 完了 最初に戻る restart() すべて初期状態に戻す 
// メッセージは、各画面にある step-message に表示する
function showStatus(msg) {
    stepMessages.forEach((el) => (el.textContent = msg));
}

function showStep(n) {
    showStatus("");                                  // 前の画面のメッセージを消す
    stepPanels.forEach((panel) => panel.classList.add("hidden"));
    document.getElementById("step" + n).classList.remove("hidden");

    stepDots.forEach((dot) => {
        const step = Number(dot.dataset.step);
        let cls = "flex-1 rounded-lg py-2 text-center text-sm font-bold ";

        // switch(true): case に条件式を書ける
        switch (true) {
            case step === n:                     // 今の画面
                cls += "bg-sky-600 text-white";
                break;
            case step < n:                      // 終わった画面
                cls += "bg-sky-100 text-sky-700";
                break;
            default:                          // これからの画面
                cls += "bg-slate-100 text-slate-400";
        }
        dot.className = cls;
    });
}

ボタンの onclick="chooseBag(true)" は、「押されたらこの関数を呼ぶ」という指定です。 入門向けの書き方で、どの関数が動くのかを HTML から読み取れます。 実務では、JS 側から addEventListener でイベントを付けるのが一般的です。あとの章で学びます。

「残高不足です。」などのメッセージは、お客さんが操作している画面の中に表示します。 showStep() は前のメッセージを消すので、 画面を切り替えるときは先に showStep()、あとで showStatus() の順に呼びます。

switch (true) と書くと、case に step === n や step < n のような条件式を書けます。 上から順に調べて、最初に true になった case を実行します。どれも当てはまらなければ default です。 値が一致するか調べる普通の switch（switch (weekday)）との違いを、見比べてみましょう。

1. 選択を変数に覚えて、合計を変える

「レジ袋を使うか」「ポイントカードがあるか」は、関数の外の変数に覚えておきます。 レジ袋を使うときだけ、合計に BAG_PRICE を足します。 

let useBag = false;         // レジ袋を使うか（true / false）
let hasPointCard = false;   // ポイントカードを読み取ったか

function getTotal() {
    return ITEM_AMOUNT + (useBag ? BAG_PRICE : 0);
}

function chooseBag(flag) {
    useBag = flag;
    updateTotal();
    showStep(2);      // 先に次の画面へ
    if (useBag) {
        showStatus(`レジ袋を追加しました。（+${yen(BAG_PRICE)}）`);
    } else {
        showStatus("レジ袋は使いません。");
    }
}

条件 ? A : B は三項演算子で、条件が true なら A、false なら B になります。 if – else を1行で書いたものです。

2. 決済方法で表示を切り替える

現金なら入金エリア、QR決済ならQRコードを表示します。表示と非表示は、 hidden というクラスを外したり付けたりして切り替えます。画面そのものを切り替える showStep() も、同じ仕組みです。 

function selectMethod(methodKey) {
    selectedMethod = methodKey;

    // いったんすべて非表示
    cashArea.classList.add("hidden");
    qrArea.classList.add("hidden");

    if (methodKey === "cash") {
        cashArea.classList.remove("hidden");       // 現金: 入金エリアを表示
    } else if (methodKey === "qr") {
        showQrCode();
        qrArea.classList.remove("hidden");         // QR: QRコードを表示
    }
    // 他の方法は何も表示しない（else は不要）
}
決済方法 methodKey 表示するもの
現金 cash 入金エリア
QR決済 qr QRコード
交通系IC・電子マネー・クレジット transit / emoney / credit なし

先に全部隠しておくと、前に選んだ方法の表示が残りません。

3. 次へ進む前のチェック（return）

進めない場合は、メッセージを出して return で関数をそこで終わらせます。これで、確認画面には進みません。 

function goToConfirm() {
    // 決済方法が未選択（"" は false として扱われる）
    if (!selectedMethod) {
        showStatus("決済方法を選択してください。");
        return;
    }

    // 現金で、かつ所持金が足りない
    if (selectedMethod === "cash" && money < getTotal()) {
        showStatus("残高不足です。チャージしてください。");
        return;
    }

    renderSummary();
    showStep(4);      // 確認画面へ
    showStatus("内容をご確認ください。");
}
書き方 意味
!selectedMethod selectedMethod が空（未選択）のとき true
A && B A かつ B（両方 true のときだけ true）
return; 関数をここで終了する

残高不足のチェックを selectedMethod === "cash" と && でつなぐのは、現金のときだけ所持金を確認したいからです。 クレジットなどでは、所持金が 0 でも決済できます。

4. 決済完了の処理

現金のときだけ、お会計の金額を所持金から引きます。ポイントカードを読み取っていれば、合計の1%をポイントとして付与します。 

function completePayment() {
    if (selectedMethod === "cash") {
        money -= getTotal();         // 所持金から引く
        updateWallet();              // 画面の所持金を更新
    }

    if (hasPointCard) {
        const point = Math.floor(getTotal() * POINT_RATE);
        resultDisplay.textContent = `${point} ポイント付与しました。`;
    } else {
        resultDisplay.textContent = "ポイントカードは使用されませんでした。";
    }

    showStep(5);      // 完了画面へ
    showStatus("決済が完了しました。");
}

5. 少し待ってから実行する（setTimeout）

注意: このレジでは、通信の待ち時間をまねるために setTimeout() を使っています。 実際の API 通信では、setTimeout() で「このくらい待てば終わるはず」と決めて使ってはいけません。 通信にかかる時間は毎回変わるので、早すぎると結果が届く前に次へ進み、遅すぎると無駄に待たせてしまいます。 通信の完了を待つときは、fetch() と async / await（または then()）を使います。あとの章で学びます。

本物のレジは、決済端末と通信するので、少し時間がかかります。この待ち時間を再現するために、 setTimeout() を使います。指定した時間が過ぎてから、1回だけ関数を実行します。 

function handlePayment() {
    payButton.disabled = true;                // 待っている間は押せない
    showStatus("決済処理中です...");

    // 1800ミリ秒（1.8秒）後に completePayment() を実行
    setTimeout(() => completePayment(), 1800);

    // ↑ ここは待たずに、すぐ次の行へ進む
}
書き方 意味
setTimeout(関数, 時間) 時間（ミリ秒）が過ぎてから、関数を1回だけ実行
setInterval(関数, 時間) 時間（ミリ秒）ごとに、関数を繰り返し実行（04 関数で学習）
1000 1000ミリ秒 = 1秒（1800 なら 1.8秒）

setTimeout() の次の行は、待たずにすぐ実行されます。待っているのは completePayment() だけです。実行の順番を、確かめてみましょう。 

console.log("1. 決済ボタンが押された");

setTimeout(() => {
    console.log("3. 1.8秒後に実行される");
}, 1800);

console.log("2. 待たずにすぐ実行される");

// 表示される順番: 1 → 2 → （1.8秒後）→ 3

setTimeout(completePayment, 1800) のように、関数名だけを渡すこともできます。 ( ) を付けて setTimeout(completePayment(), 1800) と書くと、 待たずにその場で実行されてしまうので注意しましょう。（window.onload = showTokyo; と同じ考え方です）
